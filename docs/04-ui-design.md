# 界面与文案规范

这份文档记录界面的取舍规则，不只是描述长什么样。改界面前先读这里，否则很容易把已经砍掉的冗余加回来。

## 三条原则

**1. 分层**：只把用户要用的东西放在主视觉。实现细节、术语、调试输出全部降级到折叠区或小字。

**2. 文案**：标题只做名词，不写"这是什么、用来干嘛"。一句话先给结论，术语后置。

**3. 权重**：权重由组件的**角色**决定，不由"是不是卡片"决定。

- 高：操作、风险声明
- 中：工具说明
- 低：实现方式（折叠）、致谢、版本号

## 卡片权重阶梯

| 等级 | 用途 | 视觉 |
|---|---|---|
| `Primary` | 当前主操作、已就绪的关键区块 | 白底 + 1.5dp 主色描边 |
| `Danger` | 风险与边界声明 | 极浅红底 + 1dp 淡红描边 |
| `Normal` | 普通说明 | 纯白卡片 |
| `Subtle` | 致谢、历史记录等次要信息 | 浅灰底、更小的内边距与圆角 |

一个页面里最多一个 `Primary`、一个 `Danger`。

## 状态色

| 状态 | 前景 / 背景 | 用途 |
|---|---|---|
| 已就绪 | `#1B7F4B` / `#DCF3E4` | 事务 1 完成 |
| 执行中 | `#1D5FD0` / `#DDE8FF` | 正在跑 |
| 失败 | `#B4232B` / `#FBE1E2` | 明确失败 |
| 未执行 | `#78808E` / `#EDF0F5` | 还没跑 |
| 待解锁 | `#78808E` / `#EDF0F5` | 前置条件未满足 |

状态一律用标签（chip），不用裸文字。裸文字在浅灰底上几乎看不见，这是旧版的问题之一。

## 文字层级

只有四级：

| 层级 | 规格 | 用途 |
|---|---|---|
| 标题 | 28sp Bold | 页面标题（名词） |
| 卡片标题 | 16–18sp SemiBold | 区块名 |
| 正文 | 14sp / 13sp，行高 19–20sp | 说明 |
| 说明 / 参数 | 11sp，浅灰 | keyString、字节数、构建标记 |
| 等宽 | 11sp Monospace | 原始日志 |

参数和版本号永远不与应用名竞争：`keyString 4238378` 用小字放在动作行第二行。

## 折叠政策

**进入折叠的**：实现方式、CVE 编号、两步拆分的理由、原始引擎输出。

**不允许进入折叠的**：风险声明、当前状态、失败原因、可执行的操作。

折叠默认收起。用户不看就完全不受打扰；要看随时展开。

## 导航

三个胶囊，不是通栏导航条：

- 选中态：深色填充 + 白字（不再用"点击后的阴影"表达选中）
- 未选中：半透明玻璃
- 「关于」是覆盖层，不是第三个 pager 页——这样打开它不会重置前两个页面的状态

## 文案对照

旧 → 新的替换不是"精修"，是删掉不该给用户看的东西。

| 位置 | 旧 | 新 |
|---|---|---|
| 主页副标题 | 临时提权 · 只用来打开三星 ServiceMode | 三星 ServiceMode 启动工具 |
| 主页提示 | 两个事务分开执行，失败可归因 | （删除，移到「关于」的实现方式折叠内） |
| 主按钮 | GCF 菜单 / NAS / 主菜单（两张同权重卡片） | 「建立临时 su」为主操作卡，「打开 ServiceMode」为次卡 |
| keyString | 与菜单名同级 | 小字说明行 |
| 主页说明卡 | 分两步执行 + 上次选择 | （删除） |
| 日志页标题 | 运行日志 → 执行日志 | 只保留「运行日志」 |
| 历史标题 | 运行历史（默认已存盘） | 运行历史 + 可点的说明点 |
| 关于标题 | 关于与感谢 / 这个工具做了什么，以及为什么这样做 | 关于 |
| 版本 | 独占一个胶囊条 | 标题右侧小字 |
| 关于卡片 | 这是什么 / 方法 / 两步事务 / 安全边界 / 特别感谢（五张同权重） | 安全边界（Danger）→ 工具说明 → 实现方式（折叠）→ 致谢（Subtle） |
| 致谢 | 六行流水账 | 三组：引擎与核心适配 / UI 组件 / 文档与参考项目 |
| 日志内容 | 原始 `am start`、`rc=0` 直接平铺 | 摘要一行 + 「原始输出」折叠块 |

## 间距与形状

- 页面左右内边距：20dp
- 卡片之间：12dp；区块之间：20dp
- 卡片圆角：22dp；内部元素：16dp；胶囊：50%
- 卡片内边距：17dp（`Subtle` 为 14dp）

## 已知取舍

- 「关于」用覆盖层而不是页面，代价是不能左右滑动切回；换来的是不重置页面状态。
- 运行历史的心跳判断依赖文件 mtime，秒级粒度够用，但没有"助手已退出"的主动通知。
- 折叠状态用 `rememberSaveable`，进程被杀后回到默认收起——这是有意的，默认态不制造噪音。
